# Feature Specification: 横屏/平板/折叠屏适配优化（multi-device-adapt）

**Created**: 2026-10-08  
**Status**: Draft  
**Input**: User description: "帮我优化横屏，平板，折叠屏适配"

## Overview

为 TopShowcase（媒体藏品展柜应用）建立统一的响应式断点体系，替代现有「横/竖二值判断」，使 8 种排布视图、顶栏、底部导航、详情页、设置页与各类浮层在手机横屏、平板、折叠屏（展开态）下均能以合理的布局密度与形态呈现。大屏引入内容限宽与组合视图双栏，折叠/展开切换保持浏览状态，同时不回退现有手机竖屏体验。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 统一断点感知（Priority: P1）

作为用户，无论使用手机、平板还是折叠屏打开应用，应用都能按当前窗口宽度归入正确的档位（sm/md/lg），所有界面元素依据档位而非单纯横竖屏决定布局形态；旋转屏幕、折叠屏展开、平板分屏调整窗口大小时，档位判定实时更新。

**Why this priority**: 断点体系是后续所有适配工作的地基；没有统一档位判定，各视图只能继续零散地用横竖屏二值判断修补，无法区分「平板竖屏」与「手机竖屏」。

**Independent Test**: 旋转设备 / 调整分屏窗口宽度，观察界面布局随档位切换而变化，且判定在各视图间一致。

**Acceptance Scenarios**:

1. **Given** 平板竖屏（宽度落入 md/lg 档），**When** 打开应用，**Then** 界面呈现大屏形态（而非沿用手机竖屏的拉伸布局）
2. **Given** 手机横屏与折叠屏展开态宽度相近，**When** 分别打开同一视图，**Then** 两者呈现一致的大屏布局
3. **Given** 平板分屏拖动分割线，**When** 窗口宽度跨越档位阈值，**Then** 布局实时切换且无卡死、无残留旧布局

---

### User Story 2 - 大屏内容限宽与多列密度（Priority: P1）

作为平板/折叠屏展开态用户，浏览 8 种排布（网格/瀑布/展柜/列表/展厅墙/透视长廊/旋转展台/时间轴）时，内容不会在超宽画幅上被拉伸变形或留出大片空白；列数/卡片尺寸随档位合理增加，内容区在超宽时限制最大宽度并居中。

**Why this priority**: 内容浏览是应用核心场景，8 种排布是大屏体验的主体；拉伸与稀疏留白是大屏最直观的体验缺陷。

**Independent Test**: 在 lg 档逐一切换 8 种排布，检查内容密度、无过度拉伸、无大面积空白。

**Acceptance Scenarios**:

1. **Given** lg 档下使用网格/瀑布排布，**When** 浏览藏品，**Then** 列数多于手机竖屏且每格宽度合理，图片无模糊拉伸
2. **Given** lg 档下使用列表/展柜排布，**When** 浏览藏品，**Then** 内容限宽居中，行不被拉满全宽
3. **Given** lg 档下使用展厅墙/时间轴/旋转展台，**When** 浏览藏品，**Then** 画幅利用合理，两侧无大块空白，卡片尺寸协调
4. **Given** sm 档（手机竖屏），**When** 浏览任意排布，**Then** 现有布局与列数设置完全保持不变（回归）

---

### User Story 3 - 组合视图双栏（Priority: P1）

作为平板/折叠屏展开态用户，在「组合」视图按分组浏览时，界面呈现左侧分组导航 + 右侧分组内容的双栏结构；点击左侧分组，右侧内容直接切换，无需先返回再进入。

**Why this priority**: 双栏是平板大屏空间价值最直接体现，消除大屏下来回跳转；组合视图结构天然适合双栏。

**Independent Test**: 在 lg 档进入组合视图，左侧出现分组列表，点击不同分组右侧内容即时切换。

**Acceptance Scenarios**:

1. **Given** lg 档且有多个分组，**When** 进入组合视图，**Then** 左侧显示分组导航（含全部分组入口与计数），右侧显示选中分组的藏品
2. **Given** 双栏状态下，**When** 点击左侧某分组，**Then** 右侧内容切换到该分组，左侧选中态高亮，无需页面跳转
3. **Given** sm/md 档，**When** 进入组合视图，**Then** 保持现有单栏形态不变

---

### User Story 4 - 顶栏与底导航大屏适配（Priority: P2）

作为横屏/平板用户，顶栏（标题、搜索框、排序、更多菜单）在宽屏下合理利用宽度：搜索框限宽、控件不再拥挤或分散两端；底部导航胶囊在大屏居中等距，不贴屏幕两端。

**Why this priority**: 框架层是每屏可见的骨架；但现有横屏下已有部分处理（导航居中），优先级低于内容层改造。

**Independent Test**: 在 lg 档观察顶栏各控件分布与搜索框宽度，底导航三胶囊位置居中。

**Acceptance Scenarios**:

1. **Given** lg 档，**When** 查看顶栏，**Then** 标题、搜索框、排序、更多按钮分布协调，搜索框不会拉满全宽
2. **Given** 横屏/大屏，**When** 查看底导航，**Then** 三块胶囊居中等距，不贴屏幕两端，材质背板与自绘内容同心不错位

---

### User Story 5 - 弹层与设置页限宽（Priority: P2）

作为大屏用户，打开设置页、分组编辑弹层、多选操作栏时，这些浮层不拉伸至全屏宽度，而是限宽居中（或按平台习惯贴边），信息密度合理。

**Why this priority**: 浮层出现频率低于主内容，但全宽拉伸的表单在大屏上观感廉价，属于体验细节。

**Independent Test**: 在 lg 档打开设置页与分组编辑、进入多选模式，检查浮层宽度约束。

**Acceptance Scenarios**:

1. **Given** lg 档，**When** 打开设置页，**Then** 设置面板限宽，控件行不横贯全屏
2. **Given** lg 档，**When** 进入多选模式，**Then** 底部多选操作栏限宽居中
3. **Given** lg 档，**When** 打开分组编辑弹层，**Then** 弹层宽度合理约束，不被拉满

---

### User Story 6 - 折叠屏状态保持（Priority: P3）

作为折叠屏用户，正在浏览藏品（列表滚动到中部或详情页打开中）时折叠/展开设备，界面重排后当前浏览的藏品仍保持在视口内，详情页不丢失当前项。

**Why this priority**: 折叠/展开是低频动作，状态丢失不会阻断功能，但处理好是高端体验的分水岭；且档位切换的通用状态保持（User Story 1）已覆盖大部分场景。

**Independent Test**: 在列表中部与详情页两个状态下折叠再展开，检查浏览位置是否保持。

**Acceptance Scenarios**:

1. **Given** 列表滚动到中部，**When** 展开折叠屏，**Then** 重排后视口内仍可见先前浏览位置附近的藏品（至少不跳回顶部）
2. **Given** 详情页打开中，**When** 折叠/展开设备，**Then** 详情页仍打开且显示同一件藏品，信息面板形态随档位切换
3. **Given** 沉浸式幻灯片播放中，**When** 折叠/展开设备，**Then** 幻灯片继续播放同一件藏品，图片按新画幅合理呈现

---

### Edge Cases

- 平板分屏拖到极窄（宽度落入 sm 档）：应用按手机单栏形态呈现，不出现布局破碎
- 折叠屏折叠瞬间（档位临界抖动）：断点判定做去抖，避免布局在阈值附近反复横跳
- lg 档下分组为空（没有任何分组）：组合视图双栏不出现空白左栏，降级为现有空态提示
- lg 档下选中「全部」分组：右侧内容显示全部藏品，左侧「全部」项高亮
- 时间轴/展厅墙等依赖滚动位置的排布在档位切换后：内容重新排布不产生重叠或闪烁
- 2in1 自由窗口拉伸到超宽（超过 lg 上限）：内容继续限宽居中，不随窗口无限拉伸

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 建立全应用统一共享的断点判定机制，按窗口宽度划分档位（以官方断点标准为准，验证于设计阶段），覆盖旋转、折叠展开、分屏、自由窗口等一切窗口尺寸变化来源
- **FR-002**: 断点判定 MUST 包含去抖/稳定机制，避免窗口尺寸在阈值附近抖动时布局反复切换
- **FR-003**: 网格、瀑布、列表、展柜四种常规排布 MUST 按档位提供列数/形态策略：sm 保持用户设置的列数；md/lg 自动推算合理列数，单元格宽度不超过合理上限
- **FR-004**: 展厅墙、透视长廊、旋转展台、时间轴四种画廊排布 MUST 在 md/lg 档各自优化画幅利用（列数/推进方向/卡片尺寸），不出现大面积空白或单卡拉伸
- **FR-005**: lg 档组合视图 MUST 呈现双栏结构：左侧分组导航（分组名 + 计数，含全部入口），右侧所选分组内容；sm/md 档保持现有单栏形态
- **FR-006**: 内容区在超宽画幅（lg 及以上）MUST 限制最大宽度并居中，防止单元素横向拉伸变形
- **FR-007**: 顶栏 MUST 在 md/lg 档调整控件布局：搜索框限宽，操作按钮分布协调，不随屏幕无限拉宽
- **FR-008**: 底部导航 MUST 在 md/lg 档保持居中等距形态，材质背板与自绘内容保持同心对齐
- **FR-009**: 设置页、分组编辑弹层、多选操作栏 MUST 在 md/lg 档限制宽度（居中呈现），sm 档保持现有全宽形态
- **FR-010**: 详情页 MUST 在 md/lg 档（含平板竖屏）启用左内容/右信息面板的分栏形态；sm 档保持现有上下结构
- **FR-011**: 沉浸式幻灯片 MUST 在所有档位下合理呈现：图片按画幅适配，不拉伸变形，控制层位置随安全区/档位调整
- **FR-012**: 档位/方向切换时 MUST 保持浏览状态：滚动位置对应的藏品在重排后仍位于视口内；详情页/幻灯片保持当前项不丢失
- **FR-013**: 现有四向安全区避让能力 MUST 在全部档位与方向下保持有效，不因布局重构回退
- **FR-014**: sm 档（手机竖屏及窄分屏）的现有视觉、交互与设置持久化行为 MUST 完全保持（回归约束）
- **FR-015**: 用户列数设置 MUST 仅在 sm 档直接生效；md/lg 档由系统按宽度自动推算，用户切换回 sm 档后设置仍然有效

### Key Entities

- **BreakpointState（断点状态）**: 当前档位（sm/md/lg）、窗口宽高、屏幕方向、四向安全区尺寸；随窗口变化实时更新，全应用共享
- **LayoutProfile（布局参数档案）**: 每个档位对应的布局参数集合——各排布列数、内容限宽值、组合视图双栏宽度、详情页信息面板宽度、弹层限宽值、顶栏搜索框宽度等

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 手机竖屏、手机横屏、平板竖屏、平板横屏、折叠屏折叠态、折叠屏展开态 6 种形态下，8 种排布 + 顶栏/底导航 + 详情页 + 设置页 + 3 类浮层全部无内容溢出、无控件遮挡、无图片拉伸变形
- **SC-002**: 任意两种形态间切换（旋转/折叠/分屏调整），界面在 1 秒内完成重排，无白屏、闪烁或旧布局残留
- **SC-003**: 档位切换后，切换前视口内第一件可见藏品在重排后仍出现在视口内（浏览位置保持成功率 100%，含列表、详情、幻灯片三种状态）
- **SC-004**: lg 档组合视图双栏可完成「查看全部分组 → 进入指定分组 → 返回全部」全流程，无页面级跳转
- **SC-005**: 现有手机竖屏的全部功能与设置（列数/排序/筛选/分组/主题等持久化项）在升级后行为不变（100% 回归通过）

## Assumptions

- 折叠屏展开态按窗口宽度等价归入对应档位处理，不读取铰链传感器、不做铰线贴合布局
- 折叠屏折叠态等价于 sm 档手机；2in1 的超宽自由窗口归入 lg 档并以内容限宽兜底，不单设 xl 专用布局
- 断点阈值以 HarmonyOS 官方断点标准为准（设计阶段核对最新文档），实现采用官方推荐机制
- 不改变现有视觉风格、配色、交互逻辑与数据结构；所有排布在大屏下只是布局形态变化，功能语义不变
- 现有横屏特有处理（详情页右栏、长廊横向推进、展台倒影压缩等）将迁移为基于档位的策略，行为不回退
- 设置中用户选择的列数仅在 sm 档直接生效（与现有「横屏自动推算列数」的策略方向一致）
